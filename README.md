# SmartSKU

Умные ящики для учёта мелкого крепежа: тензодатчик + NFC в каждой ячейке, ESP32 в каждом боксе, бэкенд ведёт учёт.
Идея и требования — в `CLAUDE.md`.

[Основная табличка с нужными вещами.](https://docs.google.com/spreadsheets/d/1SoUDmIfM1n-rBG37zFCyyzTNkSoC23q8NhGscTcgeVo/edit?usp=sharing)

## Текущий этап

**Сделано (этап 1: backend core + эмулятор ESP):**
- регистрация (provisioning) новых боксов по MQTT, выдача `box_id`;
- приём телеметрии `box_data`, хранение состояния ячеек, журнал событий учёта;
- калибровка: запуск из API, отправка команды на бокс, привязка компонента к NFC-метке ячейки;
- команды индикаторов (LED + дисплей) при изменении содержимого;
- эмулятор ESP32 с REST-ручками («вынуть ячейку», «насыпать/взять N штук», «вставить»);
- всё запускается в Docker; сценарий калибровки и работы проверен end-to-end.

**Этап 2 (в работе): веб-фронтенд.** Дашборд обновляется сам раз в секунду: боксы и слоты, компоненты, калибровки,
журнал событий. Действия: подключить бокс, настройка весов, запустить/отменить калибровку, освободить ячейку. Вкладки эмулятора на фронте больше нет.

**Веса в граммах, слот и ячейка (с 2026-09-21).** Данные разделены, поэтому ячейку можно переставить в любой слот
любого бокса:
- **слот** (тензодатчик в корпусе, NVS бокса) — ноль (показание пустого датчика) и масштаб (отсчётов HX711 на грамм;
  знак — направление датчика). В телеметрии — `slot_ready`;
- **ячейка** (её NFC-метка MIFARE Classic, блок 4) — вес пустой ячейки (тара) и вес штуки, в граммах. `cell_tared` —
  тара есть в метке;
- вес содержимого, г = (показание − ноль) / масштаб − тара; может быть отрицательным (не прячем), штук ≥ 0.

**Настройка весов** — редкая сервисная операция, отдельная кнопка в шапке дашборда (на карточке слота — только
подсказка-ссылка, если слоту или ячейке чего-то не хватает). Мастер: бокс и слоты (все или часть) → три шага, каждый
можно пропустить, если слот его уже прошёл:
1. **Ноль** — ячейки вынуты, площадки пустые: бокс запоминает показания пустых датчиков;
2. **Гиря** (`reference_grams` во `frontend/public/config.yaml`, 100 г) — по очереди на каждую пустую площадку:
   масштаб и направление датчика;
3. **Новые ячейки** — у каждого слота своя кнопка «Взвесить пустую» (вставить новую ячейку пустой): вес пишется в
   метку. Взвешенная ячейка помечена «✓ уже взвешена» (кнопка «Заново» — если ячейку заменили), с деталями — не взвешивается.

Дрейф датчиков — только шаг «Ноль» (масштаб прежний). Новая ячейка — только шаг «Ячейки». Каждый замер — одна команда
`scale` и один синхронный запрос `POST /api/boxes/{id}/lockers/{n}/scale`: бэкенд ждёт ответ бокса (`scale_done` /
`scale_failed` в топике `events`, до `scale.answer_timeout_seconds`), ошибка приходит 409 с причиной по-русски.

Пока слот не настроен или у ячейки нет тары, вес и количество не считаются (бэкенд пишет только `cell_inserted` /
`cell_removed`), дисплей показывает прочерки. Прочерки и у неоткалиброванной или вынутой ячейки: бэкенд шлёт
`screen_number: null`; `0` показывается только у откалиброванной пустой ячейки.

**Калибровка — пошаговый сценарий, который бокс ведёт сам** по NFC и весу и сообщает шаг в `box_data.calibration`;
фронт рисует по нему чек-лист, на дисплее слота — подсказка (`OUt` — выньте, `In` — вставьте, `HOLd` — не трогайте,
`donE` / ` Err` — итог): выньте ячейку и насыпьте N штук → вставьте → бокс считает вес штуки и пишет в метку. Если
вставить пустой — попросит вынуть снова. Нужны настроенный слот и ячейка с тарой. Итог — `calibration_done` /
`calibration_failed` с причиной; бэкенд пишет журнал и закрывает заявку.

**Подключение бокса с дашборда по Bluetooth** (проверено на плате): кнопка «Подключить бокс» → бокс в режиме
подключения (удержание кнопки подключения 3 с) → браузер по Web Bluetooth получает сведения о боксе и его слотах и список Wi-Fi
сетей → пользователь выбирает сеть и адрес сервера → статусы подключения до регистрации. Компьютер не меняет свою
сеть, прошивка не содержит ни паролей, ни адреса сервера: так же бокс переносится на другой компьютер (например,
к коллеге с его контейнерами). Новый бокс бэкенд регистрирует, только если его подключали с дашборда (claim).
Подробно — «Подключение бокса» ниже.

**Этап 3 (в работе): реальное железо.** Прошивка `firmware/smartsku_box` 0.8.2 (1 бокс, 4 ячейки; с 0.8.0 — облако по TLS, с 0.8.1 — кнопка подключения на D13, с 0.8.2 — в Bluetooth-имени первые 4 символа `hardware_id`, свои у каждой платы: последние — префикс производителя, общий для всех) на плате:
регистрация, телеметрия, NFC (метки — MIFARE Classic 1K, читаются ключом по умолчанию), HX711, дисплеи.
Тензодатчик слота 3 (locker 2, DOUT GPIO34) сломан — раньше показания скакали до 200 000, на 2026-09-21 стоят около
нуля (0…570) и не реагируют на ячейку; его не глушим, просто не смотрим на него в тестах. У датчиков разный знак и смещение (сырые показания бывают отрицательными — это нормально).
Базы бэкенда, брокера, настройка весов в плате и метки всех 4 ячеек очищены 2026-09-23 (метки — командой `e`),
бокс зарегистрирован заново (`027b5f086e31`, claim через `POST /api/onboarding/claims`); 0.7.0 прошита. 2026-09-23 прошита 0.8.0, бокс переведён в облако (`715e666489fc` на app-smartsku.online, Wi-Fi — раздача «iPhone (5)»). На 2026-09-23 все
4 RC522 видны, но считыватель слота 4 (locker 3) по разу не отвечал (`version 0x00`) и сыпал ошибками связи — проверить
проводку. Считыватели 0–2 однажды «теряли» метку и больше её не находили до перезагрузки — следить.
Осталось: проверить на железе настройку весов гирей, запись метки, калибровку и перестановку ячеек
между слотами. Метки
версии 1 бокс читает как чистые, в NVS старые ключи `emptyN`/`dirN` не используются.

**Стенды и адреса боксов (с 2026-09-24).** Боксы стыкуются в стенды (кластеры) слева, справа, сверху и снизу.
Раскладку боксы сами не сообщают (сигнального контакта в разъёме нет), её задаёт пользователь: после регистрации
в мастере «Подключить бокс» — кнопка «Указать место на стенде», дальше на вкладке «Склад» рядом с боксами стенда
появляются клетки «+ Поставить сюда». Первый бокс сразу становится `A1` нового стенда. Адрес бокса — столбец буквой
слева направо и ряд цифрой **снизу вверх** (`B1`): бокс, поставленный сверху, не меняет адреса нижних. Бокс ставится
только вплотную к другому боксу стенда; после каждого изменения сетка сдвигается так, чтобы начиналась с `A1`
(бокс, поставленный слева или снизу, перенумеровывает остальные). Стенд без боксов удаляется. На «Складе» стенд
рисуется компактной схемой, как стоит, видом спереди: у каждого бокса адрес, связь и 4 слота с количеством и
компонентом (`box-mini.ts`), так что стенд целиком помещается на экране телефона. Полная карточка — только у
выбранного на схеме бокса: справа от схемы, на узком экране — под ней. «Изменить расстановку» — на карточке
выбранного бокса переместить, дать название, убрать со стенда; переименовать стенд. Везде (журнал, калибровка, компоненты) бокс называется адресом, `hardware_id` — только пока
бокс не размещён; с несколькими стендами к адресу добавляется имя стенда. Подсветки бокса на самом железе нет —
только интерфейс.

**Дальше:** переносить во фронт остальные сценарии (поиск/фильтры компонентов, история по ячейке), миграции БД (Alembic), своя учётка брокера на каждый бокс (сейчас общая `box`), бэкапы SQLite на VPS.

## Архитектура

```
 ESP32-боксы / эмулятор ──MQTT──► Mosquitto ◄──MQTT── backend (FastAPI) ──► SQLite (backend/var/smartsku.db)
                                                          ▲
                                                 REST API │
                                  frontend (nginx + Lit) ─┘  /api проксируется на backend
```

| Сервис | Папка | Порт | Назначение |
|---|---|---|---|
| `mosquitto` | `infra/mosquitto` | 1883 | MQTT-брокер |
| `backend` | `backend/` | 8000 | бизнес-логика, REST API, Swagger: `/docs` |
| `frontend` | `frontend/` | 8080 | веб-дашборд + панель эмулятора: http://localhost:8080 |
| `emulator` | `emulator/` | 8001 | эмуляция ESP32-боксов, Swagger: `/docs` |

Правила кода: только ООП, конфиги в `config/*.yaml` (`config.local.yaml` — запуск на хосте, `config.docker.yaml` — в контейнере,
путь переопределяется `SMARTSKU_BACKEND_CONFIG` / `SMARTSKU_EMULATOR_CONFIG`), DI через dishka, пакетный менеджер uv.

Коммиты: сообщение описывает только суть изменения (первая строка — кратко, при необходимости абзац с деталями).
Без `Co-Authored-By`, подписей и ссылок на инструменты. Новая работа ведётся в ветке от `main`.

**Линтер — ruff** (настройки в `pyproject.toml` каждого проекта). Прогонять после любых изменений:
`uv run ruff format . && uv run ruff check --fix .` в `backend/` и `emulator/`. В `.claude/settings.json` настроен
хук Claude Code, который делает это автоматически после каждого редактирования `.py`-файла.

### Почему MQTT
Боксу нужно и постоянно слать данные, и мгновенно получать команды. MQTT даёт это без поллинга, у ESP32 есть готовые
библиотеки (PubSubClient) с переподключением, а механизм Last Will позволяет брокеру самому сообщить, что бокс пропал.

### Backend (`backend/src/smartsku_backend`)
- `config.py` — pydantic-модели конфига и загрузчик yaml.
- `messaging/` — `contracts.py` (JSON-контракты), `topics.py`, `publisher.py` (отправка команд), `gateway.py`
  (подключение к брокеру, маршрутизация входящих сообщений в сервисы в request-scope dishka).
- `services/`
  - `provisioning.py` — выдаёт `box_id` по `hardware_id` (идемпотентно). Новый `hardware_id` регистрируется, только
    если на него есть claim (`box_claims`, создаётся мастером подключения, живёт `onboarding.claim_ttl_minutes`);
    известные боксы получают свой id без claim;
  - `box_status.py` — online/offline бокса;
  - `telemetry.py` — ядро: сравнивает показания с сохранённым состоянием, пишет события учёта, хранит готовность
    слота, тару ячейки и шаг калибровки, формирует команды индикаторов. Количество считается только по «измеримым»
    показаниям (`slot_ready`, `cell_tared`, нет калибровки). Живое состояние (дашборд, дисплеи) меняется сразу, а в
    журнал попадает только то, что продержалось: ячейка вынута — метки нет `telemetry.removal_confirm_seconds` (1 с);
    вставлена (одна запись «было → стало», когда количество устоялось) или новое количество — держится
    `telemetry.confirm_seconds` (3 с). Полувыдвинутая ячейка, у которой метка то видна, то нет, и колебания веса после
    вставки или во время досыпания записей не дают;
  - `runtime_cache.py` — in-memory кэш последних показаний, чтобы не ходить в БД каждые 0.5 с на каждый бокс, и
    кандидаты в журнал со временем появления;
  - вес во всём проекте — в граммах (без тары ячейки); порог `telemetry.weight_change_threshold` отсекает только
    дребезг float — шум фильтрует бокс;
  - `indicators.py` — команда индикаторов: дисплей показывает количество; если ячейки нет, у неё нет тары или
    она не откалибрована — `screen_number: null`, и дисплей показывает прочерки (ноль выглядел бы как «ячейка пуста»),
    светодиод пока всегда `none` — он зарезервирован под другие сценарии;
  - `box_events.py` — отчёты бокса (топик `events`): `scale_*` — журнал и ответ ожидающему запросу,
    `calibration_done` создаёт компонент и закрывает заявку, `calibration_failed` отменяет её; причины по-русски —
    `failure_notes.py`, в `note`;
  - `scale.py` — настройка весов: `ScaleService` шлёт команду `scale` и ждёт ответ бокса через `ScaleResultWaiter`
    (APP-scope, future на слот); `calibration.py` — заявка на калибровку (слот настроен, ячейка вставлена и с тарой)
    и её отмена (команда `cancel`); `inventory.py` — чтение; `layout.py` — стенды и место бокса на стенде (проверка
    «вплотную», сдвиг сетки к `A1`, удаление пустого стенда).
- `db/` — SQLAlchemy-модели и `Database`. БД — SQLite-файл `backend/var/smartsku.db` (в Docker папка примонтирована),
  режим WAL. **Не открывайте файл с хоста (`sqlite3`, DB Browser), пока бэкенд работает в Docker на macOS:** блокировки
  и разделяемая память WAL не проходят через примонтированную папку, и база портится (так уже было). Смотреть
  данные — через REST API, или остановить бэкенд. Теги — JSON-колонка, время хранится в UTC. Таблицы создаются при старте
  (миграций пока нет). Новые колонки в существующих таблицах `Database` добавляет сам при старте (`ALTER TABLE ADD
  COLUMN`, колонка должна быть nullable или с `server_default`); для остальных изменений схемы — удалить
  `backend/var/smartsku.db*` (реальные боксы придётся перерегистрировать: `forget` в Serial Monitor).
- `api/` — контроллеры-классы и схемы ответов.

**Модель данных:**
- `boxes` — бокс (`id`, `hardware_id`, `online`, необязательное название `alias`); место на стенде — `cluster_id`,
  `grid_x` (столбец слева, с 0), `grid_y` (ряд снизу, с 0), адрес (`B1`) считается из них (`Box.address`).
- `clusters` — стенды: `id`, `name` (новый — «Стенд N», префикс `layout.cluster_name_prefix` в конфиге).
- `locker_states` — последнее состояние слота `(box_id, locker_id)`: вставлена ли ячейка, какая, вес, количество,
  `slot_ready`, `cell_tared`, `tag_error`, шаг калибровки (`calibration_step`, `calibration_pieces`); что последним
  записано в журнал — `logged_nfc_id`, `logged_quantity`.
- `components` — что лежит в ячейке, **ключ — `nfc_id`**: имя, теги, вес штуки, количество.
  Так калибровка «едет» вместе с ячейкой при перестановке в другой слот или бокс (тара и вес штуки — ещё и в метке);
  количество бэкенд считает сам по своему `piece_weight`.
- `calibrations` — заявки на калибровку (`pending` → `completed` / `cancelled`).
- `inventory_events` — журнал: `cell_removed`, `cell_inserted`, `quantity_changed`, `calibrated`
  с `quantity_before/after`; `slot_zeroed`, `slot_scaled` (`note` — отсчётов на грамм), `cell_tared` (вес — тара
  ячейки), `scale_failed` и `calibration_failed` (`note` — причина). Например, «унёс ячейку с 20 шт., вернул с 3» → `cell_inserted 20 -> 3`.

### Эмулятор (`emulator/src/smartsku_emulator`)
**Не поддерживается** (решение 2026-09-21: работаем с реальным железом). С фронта убран, протокол в нём старый —
ноль слота, `zeroed`, без настройки весов, калибровки по шагам и NFC-данных ячейки. Описание ниже — на момент, когда он работал.
- `domain/model.py` — `VirtualCell` (ячейка с NFC, содержимое уезжает вместе с ней), `VirtualBox` (логика прошивки:
  ноль слота по команде `tare`, калибровка при вставке после команды, пересчёт штук), `Fleet` (все боксы + вынутые
  ячейки «на руках»). Новый виртуальный бокс, как и реальный, создаётся без нуля: сначала вставить ячейку и нажать
  «Установить ноль» на дашборде. Боксы из `fleet_state.json`, сохранённого до появления нуля, считаются обнулёнными.
- `messaging/box_link.py` — MQTT-клиент одного бокса: provisioning, телеметрия, приём команд.
- `domain/identity_store.py` — сохраняет полученный `box_id` в `emulator/var/` (аналог NVS-памяти ESP).
- `domain/state_store.py` — состояние флота (вес в ячейках, вес штуки после калибровки, где какая ячейка, ожидающая
  калибровка) в `emulator/var/fleet_state.json`, запись после каждого изменения. Реальный бокс тоже не забывает это
  при перезагрузке: тензодатчик меряет фактический вес, а вес штуки лежит в NVS. Пока файл есть, стартовые боксы и
  ячейки из `config/*.yaml` игнорируются — чтобы начать с нуля, удалите `emulator/var/`.
- Стартовых виртуальных боксов нет (`boxes: []`), чтобы на дашборде были только реальные боксы. Виртуальный бокс
  добавляется на вкладке «Эмулятор» (или `POST /api/boxes`), свободные ячейки `cell-0001…0005` создаются при старте.
- Стартовые боксы/ячейки задаются в `config/*.yaml`. Ячейки создаются пустыми и неоткалиброванными: эмулятор ничего
  не знает о компонентах. Вес меняется ручкой `POST /api/cells/{nfc_id}/grams {"grams": 50}`;
  `POST /api/cells/{nfc_id}/pieces {"pieces": -3}` доступна только после калибровки и использует вес штуки,
  который вычислил бокс.
- В `GET /api/boxes` у слота: `nfc_flag` — вставлена ли ячейка; `calibrated_piece_weight` — вес штуки, посчитанный
  боксом (уходит в телеметрию как `piece_weight`); `pending_calibration` — бокс получил команду и ждёт вставки ячейки.

### Фронтенд (`frontend/`)
TypeScript + [Lit](https://lit.dev) (веб-компоненты — классы, в духе правила «только ООП»), сборка Vite, npm.
В Docker nginx раздаёт сборку и проксирует `/api/` на `backend:8000`. CORS не нужен.

- `public/config.yaml` — рантайм-конфиг (частота опроса, сколько событий/калибровок показывать, `box_columns` —
  слотов в ряду, `reference_grams` — вес гири); в Docker примонтирован, меняется без пересборки.
- **Слоты на карточке бокса стоят как в корпусе (вид спереди):** `locker_id` слева направо и сверху вниз, по
  `box_columns` в ряду (прототип 2×2: `1 2 / 3 4`). У каждого слота фиксированное место в сетке, поэтому слот, который
  ещё не присылал показаний, оставляет пустое место. Во всём интерфейсе номер слота = `locker_id + 1` — как подписаны
  лотки на корпусе; в API и MQTT `locker_id` по-прежнему с 0.
- **Вкладки** «Склад» (сводка, боксы), «Компоненты» (компоненты, калибровки), «Журнал» — в хэше адреса (`#journal`).
  На телефоне (≤ 720px) таблицы становятся карточками (`table.cards` в `theme.ts`), плитка ячейки подстраивается под
  свою ширину (container queries).
- **Табло слота** (`segment-display.ts`) — копия 4-разрядного TM1637: те же байты сегментов, что в
  `CountDisplay.h`, и те же правила, что `Locker::refreshDisplay`: количество, `----` (нет ячейки / не откалибрована),
  `OUt` / `In` / `HOLd` на шагах калибровки, ` OFL` больше 9999.
- **Тема**: как в системе, светлая или тёмная — кнопка в шапке (`ThemePreference`, `localStorage`, `data-theme` на
  `<html>`); цвета — в `index.html`.
- `src/api/` — `http-client.ts` (общий fetch, текст ошибки из `detail`), типы и клиент бэкенда (`client.ts`,
  копия `api/schemas.py`).
- `src/app/dashboard-store.ts` — опрашивает бэкенд (пауза, когда вкладка скрыта) и собирает данные для экрана:
  ожидающая калибровка слота, какая ячейка извлечена из пустого слота (по журналу), где сейчас ячейка компонента.
- `src/app/calibration-plan.ts` — чек-лист калибровки: шаги, тексты, надпись на дисплее слота; по шагу, который
  прислал бокс, отмечает пройденные / текущий / будущие (бокс может вернуть на шаг назад — список следует).
- `src/app/formatter.ts` — русские подписи, форматы времени/веса. `element-registry.ts` — регистрация элементов.
- `src/app/command-service.ts` — действия (замер настройки весов, калибровка, отмена, освобождение ячейки); после каждого сразу
  обновляет данные. `dashboard-events.ts` — события от карточек и таблиц всплывают в `sku-app`, который владеет
  `CommandService` и диалогами.
- `src/app/ble-box-link.ts` — Web Bluetooth канал к боксу (построчный JSON, куски по 180 байт). Работает только
  в Chrome/Edge и только на `localhost` или по HTTPS; типы API — `src/types/web-bluetooth.d.ts`.
- `src/components/` — `sku-app` (страница), `box-setup-dialog` (мастер подключения бокса), `scale-setup-dialog`
  (настройка весов: бокс и слоты → ноль → гиря по слотам → вес пустых ячеек; у каждого слота свой результат),
  `calibration-dialog` (выбор вставленной свободной ячейки с тарой → название, теги, N штук → чек-лист),
  `procedure-checklist` (список шагов: ✓ пройдены, текущий подсвечен и пульсирует, у шага — надпись дисплея),
  `box-card` (счётчик «не настроено»), `locker-tile` (что не хватает слоту/ячейке — со ссылкой в настройку весов,
  шаг калибровки с кнопками «Шаги» и «Отменить», действия «Откалибровать» / «Освободить»), `component-table`,
  `calibration-list`, `event-log` (фильтры по боксу/типу/поиску, новые строки подсвечиваются).
- Диалог калибровки можно закрыть посреди сценария: бокс продолжает, шаг виден на карточке, «Шаги» открывает чек-лист.
- Живые обновления — простой поллинг раз в секунду. Если станет тяжело, заменить на SSE/WebSocket из бэкенда.

## MQTT-протокол (контракт для прошивки ESP)

Префикс топиков `smartsku` (настраивается). JSON-примеры — `json_contracts/`.

| Топик | Направление | QoS | Сообщение |
|---|---|---|---|
| `smartsku/provision/request` | бокс → бэкенд | 1 | `{"hardware_id": "<MAC>"}` |
| `smartsku/provision/response/<hardware_id>` | бэкенд → бокс | 1 | `{"hardware_id": "...", "box_id": "..."}` |
| `smartsku/boxes/<box_id>/data` | бокс → бэкенд | 0 | `box_data.json`, каждые ~0.5 с |
| `smartsku/boxes/<box_id>/status` | бокс → бэкенд | 1, retain | `online` при подключении; `offline` — Last Will |
| `smartsku/boxes/<box_id>/events` | бокс → бэкенд | 1 | `box_event.json`: `scale_done` (`action`, `value`, `nfc_id` у `cell_tare`), `scale_failed` (`action`, `reason`), `calibration_done` (`nfc_id`, `piece_weight`, `weight`), `calibration_failed` (`reason`) |
| `smartsku/boxes/<box_id>/commands` | бэкенд → бокс | 1 | `scale_command.json`, `calibration_command.json`, `indicators_command.json`, `{"command":"cancel","box_id":"...","locker_id":0}` |

**Инициализация бокса:** при первом включении (нет `box_id` в памяти) бокс подписывается на
`provision/response/<hardware_id>`, публикует `provision/request`, сохраняет полученный `box_id` и дальше работает
с ним. Повторный запрос с тем же `hardware_id` вернёт тот же `box_id`. Незнакомому `hardware_id` без claim бэкенд
не отвечает (в логе `Provision request from unclaimed box`), бокс повторяет запрос каждые 5 с.

## Подключение бокса (Bluetooth)

Сеть и сервер бокс получает с фронта, прошивка одна для всех. Сценарий:
1. Режим подключения: удержание **кнопки подключения** (D13 / GPIO13 и GND, с 2026-09-23; раньше BOOT) 3 с, команда `setup` в Serial Monitor, или сам
   при старте, если в NVS нет настроек сети. Светодиод платы коротко вспыхивает раз в секунду. Режим закрывается через
   5 мин без действий и через 15 с после регистрации. Пока он открыт, Wi-Fi работает с энергосбережением
   (иначе ESP-IDF не пускает Bluetooth) — показания HX711 на GPIO36 могут шуметь сильнее.
2. «Подключить бокс» на дашборде (Chrome/Edge, `localhost` или HTTPS) → окно выбора `SmartSKU-XXXX` (`XXXX` — первые 4 символа `hardware_id`, на карточке бокса).
3. Фронт: `POST /api/onboarding/claims {"hardware_id"}`, затем команда `connect`. Сервер для бокса берётся из
   `GET /api/onboarding/settings` (`onboarding.*` в конфиге бэкенда): если `broker_host` задан (облако), мастер
   показывает его строкой и ничего вводить не надо — ручной ввод спрятан под «Другой сервер». Иначе (локальный стек)
   — хост страницы (если это не localhost), иначе последний введённый; IP или `имя.local` (mDNS).
   Облако: `tls=true`, порт 8883, учётка бокса (`box_username` / `box_password` из секретов бэкенда).
4. Бокс сохраняет настройки в NVS, забывает `box_id` и регистрируется заново (тот же бэкенд вернёт тот же id).
   Если сменился только сервер, Wi-Fi не переподключается.

GATT-сервис `6f1c0001-8c5b-4f5e-9a57-5b1e2a8d0c11`: RX `…0002` (write) — запросы, TX `…0003` (notify) — ответы.
Сообщения — JSON-строки с `\n` в конце, режутся на куски (бокс — под MTU, фронт — по 180 байт).

| Запрос | Ответ |
|---|---|
| `{"op":"info"}` | `{"type":"info","hardware_id","firmware","box_id","wifi":{ssid,username,connected,ip,rssi},"server":{host,port,connected},"lockers":[{locker_id,load_cell,nfc_reader,display,led,slot_ready,cell}]}` |
| `{"op":"scan"}` | `{"type":"networks","items":[{ssid,rssi,auth}]}`, `auth`: `open` / `password` / `enterprise`; до ~20 с |
| `{"op":"connect","ssid","username","password","host","port","tls","mqtt_username","mqtt_password"}` | поток `{"type":"status","state":...}` |
| неверный запрос | `{"type":"error","message"}` |

Состояния: `wifi_connecting` → `server_connecting` → `registering` → `registered` (`box_id`); ошибки
`wifi_failed` (`reason` — код `WIFI_REASON_*`: 201 сеть не найдена, 202/15/23/204 логин или пароль, 210 несовместимая
защита) и `server_failed` (`ip` бокса, `host`, `error` — код PubSubClient). При ошибках бокс продолжает попытки.
Непустой `username` — WPA2 Enterprise (PEAP), пустой `password` — открытая сеть.

**Облако: Bluetooth и TLS вместе не помещаются в память ESP32** (стек Bluedroid; с ним свободно ~57 КБ, самый
большой блок ~34 КБ — mbedTLS падает `Memory allocation failed`; без него ~100 КБ). Поэтому при `tls=true`:
`wifi_connecting` → `handover` (`ip` бокса) → через 1.5 с бокс выключает Bluetooth и только потом подключается к
брокеру. Дальше мастер следит через `GET /api/boxes`: бокс с этим `hardware_id` онлайн и `status_changed_at`
изменился после handover → «зарегистрирован»; за 60 с не появился → подсказка про закрытый порт 8883. Пока открыт
режим подключения, TLS-соединение на паузе (`MqttLink::setPaused`, бокс сам публикует `offline`).
Каждый сеанс режима подключения пересоздаёт GATT-объекты, а `BLEDevice::deinit` удаляет только сервер: бокс сам
удаляет характеристики и дескриптор (`BleSetupChannel::releaseGattObjects`), сервис ядро удалить не даёт — остаётся
~1 КБ за сеанс (было ~2.9 КБ). Если после закрытия режима свободно меньше `MIN_FREE_HEAP_AFTER_SETUP` (120 КБ,
~25 сеансов), бокс перезагружается — настройки в NVS, через пару секунд он снова на связи.
TLS: корни ISRG Root X1/X2 (`TrustedRoots.h`), время по NTP до подключения, рукопожатие ~3 с (таймаут 20 с).

Ограничения: ESP32 видит только 2.4 ГГц (у iPhone — «Максимальная совместимость»; раздача iPhone видна новым
устройствам, пока открыт экран «Режим модема»). Пароль по Bluetooth идёт без шифрования — режим открывается только
кнопкой и на 5 минут.

**Требования к прошивке** (`box_data.json`, `box_event.json`):
- без ячейки: `nfc_flag=false`, `nfc_id=""`, `weight=0`;
- `weight` — вес содержимого в граммах (без тары) и только если `slot_ready` и `cell_tared` и нет калибровки, иначе 0;
  `piece_weight` — из метки ячейки, г (0 — не откалибрована), `number_of_pieces` — посчитанное боксом (≥ 0);
- `slot_ready` — у датчика есть ноль и масштаб; `cell_tared` — в метке вставленной ячейки есть тара;
  `tag_error` — метку не прочитать;
- `calibration` — `null` или `{step, num_of_pieces}`, шаги: `remove_cell`, `insert_filled`, `measure_pieces`;
- команда `scale` (`action`: `zero` — слот без ячейки; `reference` + `grams` — гиря на пустой площадке, нужен ноль;
  `cell_tare` — вставлена пустая ячейка, слот настроен) — один замер: бокс ждёт устоявшийся вес (до 5 с) и отвечает
  `scale_done` (`value`: сырой ноль / отсчётов на грамм со знаком / тара в граммах) или `scale_failed`;
- команда `calibration` запускает сценарий, `cancel` — останавливает без события. Пока идёт замер или калибровка,
  новая команда получает отказ `busy`, текущая продолжается;
- причины ошибок: `busy`, `load_cell_failed`, `cell_present`, `no_cell`, `slot_not_zeroed`, `slot_not_ready`,
  `unstable`, `no_weight_change`, `tag_unsupported`, `tag_write_failed`, `cell_not_tared`.
- Формат метки (`CellTag.h`): 16 байт — «SK», версия 2, флаги, тара float (г), вес штуки float (г), CRC-16. MIFARE Classic —
  блок 4 с ключом A `FF…FF`, Ultralight/NTAG — страницы 4–7. Запись проверяется чтением.

## Запуск

```bash
docker compose --profile emulator up -d --build   # всё вместе
docker compose up -d                              # без эмулятора (реальные ESP)
docker compose --profile emulator down            # остановить
# профиль нужен в любой команде: без него compose гасит контейнер эмулятора
rm -rf backend/var emulator/var                   # сбросить БД, идентичности и состояние боксов
```

Локальная разработка (инфраструктура в Docker, код на хосте):
```bash
docker compose up -d mosquitto
cd backend && uv run python -m smartsku_backend
cd emulator && uv run python -m smartsku_emulator
uv run ruff format . && uv run ruff check --fix . && uv run pytest   # в backend/ и emulator/
cd frontend && npm install && npm run dev   # http://localhost:5173, /api проксируется на localhost:8000
npm run build                               # tsc (проверка типов) + сборка
```

### Облако (VPS, https://app-smartsku.online)
VPS 171.22.132.23 (Ubuntu 24.04, 1 vCPU, 2 ГБ ОЗУ + 2 ГБ swap, 30 ГБ), код в `/opt/smartsku`, вход по SSH-ключу
(`ssh smartsku-vps`). Поверх обычного compose — `docker-compose.prod.yml`: наружу торчит только Caddy (80/443,
сертификат Let's Encrypt сам, дашборд под `basic_auth`), остальные сервисы без опубликованных портов — Docker
публикует порты в обход `ufw`. Секреты — `.env` на сервере (образец `.env.example`, в git не попадает).
`ufw`: открыты 22, 80, 443, 8883.

**Сделано:** дашборд и API по HTTPS; боксы подключаются к облаку по MQTT + TLS на 8883 (прошивка 0.8.0, проверено на
плате через раздачу iPhone). Брокер (`infra/mosquitto/mosquitto.prod.conf`): без анонимов, пароли —
`secrets/mosquitto/passwd`, права — `infra/mosquitto/acl` (`backend` — всё, `box` — регистрация и
`smartsku/boxes/#`); 1883 — только внутри Docker для бэкенда. Сертификат — тот же Let's Encrypt от Caddy: его

Пока одна общая учётка на все боксы; дальше — своя учётка на бокс (выдаётся по claim).

### Прошивка ESP32 (`firmware/`)
Скетч Arduino IDE (`.ino` называется так же, как папка). Проверено на DOIT ESP32 DEVKIT V1 (ESP32-D0WD-V3),
пакет esp32 3.3.x (старый 1.0.6 не собирается на macOS: требует `python`).
Настройки прошивки — `AppConfig.h` (YAML на ESP нет). Сеть и адрес сервера задаются с фронта по Bluetooth и хранятся
в NVS. `secrets.h` (копия `secrets.example.h`, в `.gitignore`) необязателен: если он есть, бокс берёт из него настройки
при первом включении, пока в NVS пусто.
**Плата в Arduino IDE — «ESP32 Dev Module», Partition Scheme — «Huge APP»**: с Bluetooth прошивка ~1.8 МБ и не
влезает в стандартные 1.3 МБ (в профиле DOIT DEVKIT V1 нет выбора разметки). NVS лежит там же (`0x9000`), поэтому
`box_id` и данные слотов при смене разметки сохраняются. OTA в этой разметке нет.
- `firmware/smartsku_box/` — **прошивка бокса** по MQTT-протоколу выше, 4 ячейки (добавить ячейку = строка в
  `AppConfig::LOCKERS` и `LOCKER_COUNT`; пин -1 — компонента нет). Схема — из `four_tray_hardware_test.ino`
  (тестовый скетч коллеги); лоток N на плате = `locker_id` N-1. Общие линии: SCK всех HX711 = 32, CLK всех TM1637 = 33,
  SPI всех RC522 (SCK=22 MISO=21 MOSI=23) и RST=16. Свои у каждой ячейки:

  | locker_id | HX711 DOUT | TM1637 DIO | RC522 SS |
  |---|---|---|---|
  | 0 | 36 | 25 | 19 |
  | 1 | 39 | 26 | 18 |
  | 2 | 34 | 27 | 5 |
  | 3 | 35 | 14 | 17 |

  Светодиоды — через расширитель PCF8575 (I2C SDA=4 SCL=15, адрес 0x20, общий анод: LOW = горит), в прошивке пока нет.
  - `WifiConnection` — WPA2 Enterprise по логину/паролю, пароль или открытая сеть; асинхронный поиск сетей (на время
    поиска попытка подключения приостанавливается — иначе ESP32 отказывает), причина последнего обрыва.
    `MqttLink` — PubSubClient, адрес из настроек (IP или `.local` через mDNS), переподключение, Last Will, смена сессии
    после получения `box_id`.
  - `NetworkSettings` — Wi-Fi и брокер; `SecretsSeed` — необязательные значения из `secrets.h`.
  - `BleSetupChannel` — GATT-сервис настройки (BLE из ядра ESP32, Bluedroid): очередь запросов под мьютексом, ответы
    уведомлениями кусками под MTU; стек включается на время режима и выключается целиком (`deinit`).
  - `SetupController` — режим подключения: запросы `info`/`scan`/`connect`, статусы, окно 5 мин.
    `HoldButton` — удержание кнопки подключения (GPIO13).
  - `BoxApp` — настройки сети, режим подключения, provisioning (`box_id` в NVS), телеметрия раз в 0.5 с, команды
    `scale`/`calibration`/`cancel`/`indicators`, публикация итогов в `events`. Светодиод платы: вспышка раз в секунду — режим подключения, часто мигает —
    нет брокера, редко — ждёт `box_id`, горит — работает.
  - `LoadCellBus` — все HX711 на общем SCK: такт сдвигает данные во всех датчиках сразу, поэтому они читаются
    вместе за одни 25 тактов. Чтение ждёт готовности всех живых датчиков (до 200 мс); датчик, молчащий дольше 1 с,
    больше не ждут, и остальные работают без него. Библиотека HX711 не нужна.
  - `Locker` — ячейка: `LoadCell` (среднее отсчётов шины по окну 0.5 с; 3 пустых окна — ошибка датчика),
    `NfcReader` (RC522; опрос WUPA, ячейка «вынута» после 3 пропусков подряд), `CountDisplay` (TM1637),
    `IndicatorLed` (пины пока -1). Считыватели `BoxApp` опрашивает по одному раз в 50 мс (каждый — раз в 200 мс),
    антенна включена только на время опроса: соседние RC522 иначе мешают друг другу, а опрос без метки блокирует
    цикл на ~30 мс. RC522 не сбрасываются вместе с ESP32, поэтому на старте прошивка сама дёргает общий RST и
    держит его в HIGH (библиотеке RST не передаётся — она оставила бы линию плавать). Исправный считыватель без
    метки отвечает таймаутом; 50 ошибок связи подряд (~10 с) — считыватель настраивается заново.
    `NfcReader` читает данные ячейки из метки сразу при вставке (`CellTag.h`) и пишет их по запросу в тех же
    опросах; тип метки пишется в лог при вставке.
    **Вес — в граммах** (формула — в «Веса в граммах» выше и в `AppConfig.h`).
    Стабильность: окна подряд с разницей < `NOISE_UNITS` (сырые отсчёты); замер (ноль, гиря, тара, порция) —
    среднее по стабильной серии (до 8 окон), начатой после команды. Отправляемый вес меняется с гистерезисом: при
    сдвиге ≥ `min(REPORT_STEP_GRAMS, вес штуки / 2)`. После вставки ячейка не попадает в `box_data`, пока вес не
    устоится (3 стабильных окна, максимум 5 с) — кроме времени калибровки: тогда слот отправляется всегда, чтобы
    фронт видел шаг.
    Дисплей: `HOLd` во время замера, подсказки шагов калибровки, итог 2.5 с, иначе `screen_number` от бэкенда (`null` — прочерки), без связи —
    количество, посчитанное самим боксом.
  - `BoxStorage` (NVS): настройки сети, `box_id`, ноль (`zeroN`) и отсчётов на грамм (`scaleN`) каждого слота.
    Данные ячеек — только в их метках.
  - `ServiceConsole` — наладка через Serial Monitor (115200): те же замеры, что в настройке весов: `z [N]` — ноль,
    `w [N] [граммы]` — гиря (по умолчанию 100 г), `c [N]` — тара вставленной пустой ячейки, `e [N]` — стереть данные
    ячейки в её метке; `x [N]` — отменить
    калибровку, `s` — статус, `v` — показания раз в секунду (`raw`, ноль и отсчётов на грамм, вес в граммах,
    тара и вес штуки из метки, `content`; `nfc N/M` — удачные опросы из всех за секунду и код последнего,
    `err 0x..` — ErrorReg RC522), `forget` — забыть `box_id`, `reset` — стереть `box_id` и настройку весов (сеть и
    метки ячеек остаются), `setup` — режим подключения по Bluetooth.
    После `reset` или очистки БД бэкенда бокс регистрируется заново, только если на него есть claim
    (`POST /api/onboarding/claims` или мастер подключения).
  - `nfc_id` — UID метки в hex без разделителей (`04A1B2C3`).
- Библиотеки: PubSubClient, ArduinoJson 7, MFRC522 (miguelbalboa), GyverTM1637; BLE и ESPmDNS — из ядра.

**Сборка из терминала** (`arduino-cli` из brew; `downloads.arduino.cc` отдаёт 403, поэтому библиотеки ставятся
`git clone` в `~/Arduino/libraries`, а `ctags` собран из исходников `arduino/ctags` в
`~/Library/Arduino15/packages/builtin/tools/ctags/5.8-arduino11/`):
```bash
FQBN=esp32:esp32:esp32:PartitionScheme=huge_app,UploadSpeed=115200
arduino-cli compile -b $FQBN firmware/smartsku_box
arduino-cli upload  -b $FQBN -p /dev/cu.usbserial-XXXX firmware/smartsku_box
```
На 921600 (скорость по умолчанию) загрузка на нашей плате обрывается — нужен `UploadSpeed=115200`
(в Arduino IDE: Tools → Upload Speed). Открытие Serial-порта перезагружает плату (`box_id` и ноль
и данные слотов сохраняются), а если порт закрыть скриптом (pyserial), плата может остаться в сбросе и замолчать — порт нужно держать
открытым или переподключить USB. Serial Monitor в Arduino IDE так не делает.

**Первый запуск бокса:** `docker compose up -d --build` → прошить → открыть http://localhost:8080 в Chrome →
«Подключить бокс» (новый бокс сам в режиме подключения, иначе зажать кнопку подключения на 3 с) → выбрать сеть и адрес компьютера
→ дождаться «Бокс на складе» → «Настройка весов» (ноль, гиря 100 г на каждый слот, пустые ячейки) → «Откалибровать»
на карточке и идти по чек-листу.

### Сценарий калибровки
Кнопка «Калибровка» вверху или «Откалибровать» на карточке слота → выбрать вставленную свободную ячейку (слот
настроен, у ячейки есть тара) → название, теги, N штук → чек-лист; шаги отмечаются сами по действиям у стенда.
Итог — «1 шт = … г», компонент появляется в таблице, количество считается.

Через API: `POST /api/calibrations {"box_id","locker_id","name","tags","num_of_pieces"}`, дальше руками у бокса,
ход — в `GET /api/lockers` (`calibration.step`), итог — `GET /api/calibrations`, журнал — `GET /api/events`.

### REST API бэкенда
- `GET /api/boxes` — с местом на стенде (`cluster_id`, `grid_x`, `grid_y`, `address`) и названием `alias`
- `GET /api/clusters`, `PATCH /api/clusters/{id} {"name"}` — стенды
- `PUT /api/boxes/{box_id}/placement {"cluster_id", "x", "y"}` — поставить бокс вплотную к боксу стенда (`x`/`y` могут
  быть `-1`: слева от `A` / под рядом `1`), `cluster_id: null` — новый стенд с этим боксом в `A1`, 409 — место занято
  или не рядом; `DELETE /api/boxes/{box_id}/placement` — убрать со стенда; `PATCH /api/boxes/{box_id} {"alias"}`
- `GET /api/lockers?box_id=&free=`
- `POST /api/calibrations`, `GET /api/calibrations?status=`, `DELETE /api/calibrations/{id}` (отменить заявку)
- `GET /api/components?search=&tag=`, `DELETE /api/components/{nfc_id}` — освободить ячейку под другой компонент
- `GET /api/events?box_id=&nfc_id=&limit=`
- `POST /api/boxes/{box_id}/lockers/{locker_id}/scale {"action": "zero"|"reference"|"cell_tare", "grams"}` — замер
  настройки весов; ждёт ответа бокса, отвечает `{action, value, nfc_id}` или 409 с причиной
- `POST /api/onboarding/claims {"hardware_id"}` — ждать регистрации этого бокса; `GET /api/onboarding/settings` —
  адрес брокера для боксов

## Открытые вопросы
- Гиря на настройке ставится на пустую площадку слота (без ячейки). Если на площадку без ячейки её не поставить —
  перейти на схему «гиря в пустой ячейке» (масштаб по разнице, тара — заодно).
- Мастер подключения с другого компьютера по сети (не `localhost`) требует HTTPS в nginx.
- Шифрование канала настройки (PoP).
- В каких сценариях зажигать светодиод (`red`/`green`) — решим позже, пока он не горит.
- Mosquitto без авторизации и TLS — только для локальной сети.
